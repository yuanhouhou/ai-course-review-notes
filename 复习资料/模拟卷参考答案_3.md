## 一、基础简答题

### 1. 搜索问题建模与 A* 搜索

状态可表示机器人当前位置，动作是向相邻可通行位置移动；初始状态为仓库入口，目标测试为到达指定货架，路径代价可累计距离、时间或能耗。广度优先搜索适合每步代价相同、需找最少步数的情形，但状态空间大时开销较高。A* 用 `f(n)=g(n)+h(n)` 同时考虑已走代价和到目标的估计代价，适合有位置距离等启发信息的路径规划。`h(n)` 不高估真实剩余代价时是可采纳的，能保证找到最优解；高估可能使算法过早放弃实际更优路径。

### 2. 逻辑表示、推理与不确定性

命题逻辑用整体命题及连接词表达，如 `P→Q`，表达简单但难描述对象、属性和量词关系；一阶谓词逻辑可用谓词、变量和量词表达一般规则。可写为 `∀x (PassedSafety(x) → Allowed(x))`，已知 `PassedSafety(R1)`，由全称实例化和肯定前件推出 `Allowed(R1)`。但传感器读数常有误差、规则前提也可能不完全确定，确定性逻辑只能给出真/假结论。此类场景可结合概率模型、置信度或人工复核，而不能把低置信度观测当作绝对事实。

### 3. 优化、梯度下降与泛化

模型以训练样本的预测与标签构造损失函数，反向传播计算各参数对损失的梯度，梯度下降沿负梯度方向更新参数。学习率过大可能震荡或发散，过小则收敛慢。训练集用于更新权重；验证集不更新权重，用于选择学习率、结构和最佳检查点。训练损失下降而验证损失上升通常表示过拟合，即模型开始记忆训练数据中的偶然模式。可使用早停并恢复验证集最优权重，也可采用数据增强、正则化、Dropout、减少模型复杂度或增加有效训练数据。测试集应留到方案确定后最终评估。

## 二、前沿简答题

### 4. 多模态融合的价值与评测

照片可提供外观和位置，语音可提供现场描述，工单给出历史和规范；对齐后模型可相互校验并处理单一模态缺失。应评测故障判断准确率/召回率、跨模态一致性、噪声或缺失模态下的鲁棒性、建议的安全合规率、推理时延和人工复核通过率。简单拼接不保证模型知道哪段语音对应哪处图像，也不能解决输入互相矛盾、时间不同步和错误信息传播问题；需通过表示学习、对齐机制、冲突处理和真实任务评测证明融合有效。

### 5. 从 Copilot 到 Agent 的工作流与边界

Copilot 主要根据用户当前指令提供建议，通常不自主执行外部操作；Agent 可分解目标、规划步骤、调用检索和写入等工具并根据反馈调整。流程可为：接收范围和权限→检索并记录来源→去重分类→生成带引用的摘要→核验关键结论→展示待写入差异→经负责人确认后写入→保留日志与可撤销版本。它只能访问授权论文库和指定知识库目录，不能读取无关私人文件；对发布、覆盖、删除及含敏感信息的写入必须人工确认。还应防范提示注入、伪造引用和越权工具调用。

### 6. 大模型能力评估与可信使用

参数量和榜单仅反映部分条件下的能力；数据质量、架构、推理策略、领域适配、工具和评测集都会影响实际效果。应以真实维护任务评测事实正确率、引用可追溯率、危险建议拒答率、人工审查通过率、端到端时延、单任务成本、异常输入鲁棒性和服务可用性。治理上应使用版本化且经授权的知识库，关键建议要求证据与人工确认，按最小权限隔离工具，记录输入/输出和调用日志，并持续监控错误案例、数据漂移与成本。真实环境有噪声、长尾故障和责任约束，不能由一次离线榜单替代。

## 三、编程题

### 7. CNN 分类器维度与训练模式改错

两次池化使空间尺寸 `32→16→8`，故全连接层应为 `nn.Linear(16 * 8 * 8, 10)`。展平必须保留 batch 维：`x = torch.flatten(x, start_dim=1)`，得到 `[batch_size, 1024]`；原写法会把 batch 一并合并。`CrossEntropyLoss` 接收原始 logits，最后应为 `return self.fc(x)`，不应额外使用 `softmax`。

### 8. 训练与验证循环理解

`model.train()` 使 Dropout 按训练规则随机失活、BatchNorm 使用当前批统计量；`model.eval()` 关闭 Dropout 随机性，并让 BatchNorm 使用已累计的统计量。`torch.no_grad()` 关闭梯度记录，减少验证的显存和计算开销。验证集不参与反向传播或 `optimizer.step()`，否则验证数据会泄漏到参数和模型选择过程中；它只用于比较检查点、调整超参数和早停。
